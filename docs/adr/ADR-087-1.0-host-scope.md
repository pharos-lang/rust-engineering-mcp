# ADR-087 — Alcance de hosts para 1.0 y aclaración de spec

Date: 2026-09-14

## Context

D13 (`docs/roadmap/adr-backlog-m2-m8.md` §D13) exige, con alcance antes de
M8-02 y resolución en M8-07, decidir si 1.0 califica y publica más de la
familia de host ya positiva desde 0.1.0 (ADR-048). La spec describe una matriz
aspiracional de cinco triples en §61 («GitHub Releases») y lista
`cross-platform` entre los criterios de §97 («1.0.0») sin fijar qué families
cuentan como calificadas. El estado verificado en M8-01
(`docs/validation/M8/delegation/D13-scope-brief.md`) es:

| Familia | Host positivo | Artifact | CI |
| --- | --- | --- | --- |
| macOS ARM64 (26/APFS + Docker Linux ARM64 gateway) | Sí, M0–M6 calificados nativamente (ADR-048, gates `full`) | `v0.1.0`, `v0.3.0` core archive | portable + full local |
| Linux x86_64 | No (sin adapter no-follow/reparse-safe ni oráculos nativos) | Ninguno | portable (fmt/check/clippy/test/doctests/architecture) + SonarCloud coverage |
| Windows x86_64 | No | Ninguno | **Retirado** el 2026-09-13 (regresión stdio pre-`initialize` de M6, `docs/ci.md`) |
| Linux ARM64 / macOS x86_64 | No | Ninguno | Ninguna |

Calificar un host positivo nuevo exige un adapter de filesystem no-follow/
reparse-safe, oráculos de seguridad nativos (equivalentes a G4), un host real
para el gate y, para Windows, además corregir la regresión de stdio
pre-`initialize` retirada del CI el 2026-09-13. Ninguna de esas piezas existe
hoy fuera de macOS ARM64. El plan M8 (`docs/roadmap/m8-stabilization.md`
§«Performance, operación y distribución») reserva al owner la opción de
limitar 1.0 a macOS, condicionada a que esa opción se documente con un ADR y
una aclaración explícita de spec §61/§97 antes del freeze.

## Decision

1. **1.0 se califica y publica para un único host positivo: macOS ARM64
   (macOS 26/APFS) con el gateway Docker Linux ARM64 fijado** para toda
   ejecución de código de proyecto. El artifact 1.0 es el core
   `aarch64-apple-darwin`, la misma frontera de artifact que fijó ADR-048 para
   0.1.0, ahora vigente para 1.0.
2. **Linux x86_64 y Windows x86_64 siguen siendo targets de portabilidad de
   fuente/protocolo/fail-closed en CI, no calificados.** No reciben adapter
   no-follow/reparse-safe, no reciben oráculos nativos G4, no reciben
   artifact. El CI de Windows, retirado el 2026-09-13 por la regresión de
   stdio pre-`initialize`, se restaura si esa regresión se corrige dentro de
   M8; su restauración cuenta como **deuda de portabilidad**, nunca como
   criterio 1.0. Linux ARM64 y macOS x86_64 no se anuncian ni se prueban en
   CI.
3. **El criterio `cross-platform` del checklist 1.0**
   (`docs/roadmap/m8-stabilization.md`) se cierra como **«resuelto por cambio
   de alcance aprobado por el owner»**; nunca se marca como cumplido en el
   sentido de la matriz aspiracional de spec §61. Calificar una familia
   adicional en el futuro requiere un subprograma D13 propio: adapter de
   filesystem, oráculos nativos, host real y un ADR nuevo que enmiende o
   suceda a este.
4. Esta decisión se registra en sesión el 2026-09-14 por el owner técnico
   («Aprobado A», sobre la opción A del brief
   `docs/validation/M8/delegation/D13-scope-brief.md`) y en
   `docs/validation/M8/02.md` decisión 8.

## Alternatives considered

- **B. 1.0 con Linux x86_64 positivo además de macOS.** Exige un subprograma
  D13 completo: adapter de filesystem no-follow (`openat2`/`RESOLVE_*`),
  sandbox nativo o gateway Docker en host Linux, oráculos nativos G4 y un host
  Linux real para el gate; artifact Linux con smoke desde descarga limpia.
  Descartada para 1.0 por tamaño (XL), por requerir hardware/host Linux y
  sesiones adicionales que alargarían M8-07/M8-09 sin fecha firme.
- **C. Tres familias positivas (macOS + Linux + Windows).** Añade a B la
  corrección de la regresión stdio pre-`initialize`, adapters reparse-safe y
  junctions, y sandbox nativo de Windows. Descartada: no es alcanzable dentro
  de M8 sin hosts adicionales ni decisiones de owner adicionales; no se
  recomienda para 1.0.

## Consequences

- README, `docs/compatibility.md`, `docs/ci.md` y spec §61/§97 quedan
  coherentes: macOS ARM64 es el único host positivo y el único artifact 1.0;
  Linux/Windows son CI de portabilidad, no soporte funcional.
- `docs/publication.md` y ADR-047/ADR-048 no cambian: la frontera de artifact
  y licencia que fijó ADR-048 para 0.1.0 se confirma, no se sustituye, para
  1.0.
- M8-07 califica exactamente un target (macOS ARM64); no produce evidencia de
  calificación para ninguna otra familia.
- La aspiración de spec §61 (cinco triples) se mantiene en el texto como
  aspiración explícitamente no cumplida en 1.0, con una nota que enlaza a este
  ADR; no se borra ni se reescribe la matriz aspiracional.
- Una familia adicional entra al soporte positivo únicamente mediante un
  subprograma D13 nuevo: adapter de filesystem, oráculos nativos G4, host real
  y un ADR que enmiende o suceda a ADR-087.

## Status

Accepted.
