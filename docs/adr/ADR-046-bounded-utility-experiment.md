# ADR-046 — Bounded local utility experiment

## Status

Accepted and executed for M1-16 private research under the approved v2 freeze.
No product architecture, public tool, distribution or platform scope change.

## Context

Specification§94 requires real repair and offline selection comparisons. A prompt
asking a general coding agent to avoid shell access cannot establish equal
authority or protect the host from submitted Rust. M1 production permits only its
existing approved gateway. V1 proposed96 runs with several unauthored/unqualified
fixtures; [protocol v2](../validation/M1-16-protocol.md) records the prospective
24-run pilot, changed corpus and limits before utility measurement.

## Decision

Use the installed Codex0.153.0 app-server as a client API with explicit
gpt-5.6-sol/medium, ephemeral sessions, no thread environments and no native
effect tools, other MCPs, skills, hooks, plugins or inherited project instructions.
The host's supported authentication is used normally; credentials are never copied
to research artifacts. Pin and verify effective configuration and exact model.

This model uses code-mode callbacks. The installed narrow V8 host is source-reviewed:
no Node filesystem/process/network globals or imports are exposed, and callback
indices resolve only admitted tools. This is the confinement claim, not an OS
sandbox or a bound on arbitrary V8 heap/CPU. Harmless clock/plan/user-input metadata
utilities may remain equally available; all unadmitted app-server requests fail
closed. No program submitted as a repair executes on the host.

A trusted private broker grants identical three-file reads and complete src/lib.rs
submissions. It uses directory handles/no-follow checks, immutable Cargo files,
and stores candidates outside visible workspace roots. Semantic source constraints
are independently reviewed, not inferred from a filename check.

Arm A receives raw results from the existing RustGateway and the exact plain
catalog projection; arm B receives the13 unchanged MCP tools and authorized
Resources through rmcp3.2.0 client SDK. A standalone closed JSON-line control IPC
connects the broker to that SDK/gateway. It is not a replacement MCP server or a
second implementation of MCP JSON-RPC. Research binaries stay separate from the
product workspace and do not add public commands/dependencies.

The same approved Docker runtime, closed commands,30s command limits and capture
closure protect both arms. Host driver/server IP outbound traffic is denied by
sandbox-exec, permitting the Unix Docker socket; the project runtime independently
enforces its calibrated network denial. LLM service communication belongs to the
trusted host, so the entire experiment is not claimed air-gapped.

Use actual version-specific registry metadata retained with URLs/UTC/hashes, plus
source-grounded API annotations shared identically. Build SQLite, sign a public
seed42 research fixture, import via the real CLI, rebuild persistent E5/LanceDB,
and record exact identities. This trust proves local fixture integrity only, not
an approved publisher/global registry snapshot. Empty dependency/advisory
collections were not acquired and are explicitly qualified.

All admission limits, first/final oracles and interpretation are frozen before
measurement. Cancellation stops admission, interrupts the model and joins handler,
SDK server and gateway cleanup; cleanup may extend the900s window. Forced stop or
missing join evidence or cleanup uncertainty is infrastructure failure. Read-only
Docker absence observations before/after each run are required; a joined handler
alone does not establish resource cleanup. Token updates are cumulative;
partial/missing usage is retained honestly. Final oracles and independent source
review receive hidden data only after participant completion.

## Alternatives considered

- General shell-enabled agent: fails equal-authority and containment requirements.
- Prompt-only no-shell restrictions: unenforced.
- Handwritten MCP transport: duplicates rmcp and invalidates compatibility evidence.
- Harness-only or synthetic outcomes: cannot test the required utility hypotheses.
- Run the unauthored96-run proposal immediately: lacks qualified corpus/oracles.
  A prospectively amended small pilot yields limited real evidence without
  claiming the larger study or its absent task families.

## Consequences

Results apply to one model, four authored std-only repairs and four selection
intents in two languages, one repetition per item. No inference about async,
feature/dependency/vulnerability repairs or general population effects follows.
The brokered Codex participant is an actual agent workflow through the SDK; it
does not independently qualify a stock Codex MCP configuration or Inspector UI.
Native targets, licensing/publisher and final M1 DoD remain separate gates.

The completed pilot produced 12/12 first/final passes in each arm and no discordant
pair. It therefore provides no observed success advantage for B in this corpus.
B used more tool requests, elapsed time and tokens in the fixed execution. These
are descriptive observations with cache/order confounding, not causal or population
estimates. Exact evidence is retained in the
[measurement report](../research/m1-16/measurement/REPORT.md).

### Qualification clarification

Dynamic names reversibly replace dots with underscores, while public MCP names,
schemas and payloads stay unchanged. B has17 callbacks:13 MCP tools, Resource read
and3 shared closed file/submission operations. A has6. Common prompts disclose all
admission constraints. The effective41-key configuration is guarded exactly, with
host proxy policy left unchanged; no full native-tool inventory is claimed.
The neutral app-server cwd is private and outside repository/evidence ancestors.
Thread persistence is suppressed by ephemeral in pinned Codex source; ordinary
host service/auth/usage metadata is outside that narrower claim.
