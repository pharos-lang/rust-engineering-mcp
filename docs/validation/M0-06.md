El reporte [JSON real](M0-06-sandbox-report.json) contiene instante de observación,
engine/image/configuration fingerprint y cada execution fingerprint. Es un artifact
histórico; no es credencial ni cache aceptada por el runtime. Cambios de identidad
rechazan ejecución y evidencia de otra configuración no pasa admisión.
Unavailable se distingue de degraded y verified; fallo de infraestructura produce
cero garantías anunciadas. Uso inválido exit2, unavailable/degraded exit1, verified
exit0; stdout JSON fuera del modo stdio, sin contaminación del protocolo MCP.

## Oráculos observados

| Garantía | Evidencia discriminante |
| --- | --- |
| Network | 10 casos de socket reciben EPERM: cuatro tuplas IP familia/transporte con etiquetas DNS/loopback, más UNIX y NETLINK. El perfil control solo añade socket y permite las diez creaciones. No realiza tráfico, conexiones o consultas DNS. |
| Filesystem | Canary 0666 devuelve EROFS; /work permite write; rootfs contenido intacto tras 256 swaps de symlink y 512 aperturas concurrentes. Control con rootfs RW permite write. Sin mounts/volúmenes del host en configuración inspeccionada. |
| Environment | Exactamente GOMAXPROCS/HOME/HOSTNAME/PATH/TMPDIR permitidos; gate añade canary sintético al entorno padre y no aparece en guest. |
| Children | Doble fork, setsid, grandchild huérfano adoptado por PID1 y pgroup=child_pid diferente al padre; timeout seguido de rm --force y lista exacta vacía. |
| Wall/output | 1500 ms fase attach y timeout; output concurrente supera 4096 bytes por stream y termina OutputLimit, retenido <=4096 por stream. Gate separado prueba cancelación y recuperación. |
| CPU | cpu.max=50000 100000; nr_throttled y throttled_usec aumentan tras trabajo CPU. |
| Memory | memory.max=67108864; allocaciones tocadas, exit137 y State.OOMKilled=true, no inferencia solo por exit137. |
| PIDs | pids.max=64, pids.events max aumenta y el spawn encuentra EAGAIN; 256MiB en este escenario separa PID del límite RAM. |
| Disk | tmpfs /work 8MiB se llena y devuelve ENOSPC; /tmp 8MiB, /dev/shm 1MiB y rootfs RO, resto de mounts sin autoridad writable para UID65532. |

La frontera filesystem viene del namespace/mounts verificados y seccomp; el canario
host ausente es una observación auxiliar, no la prueba única. No se ha acreditado
transferencia del filesystem del proyecto ni mounts vivos resistentes a TOCTOU.
Daemon/host/imagen/binario son TCB. Falla del daemon puede impedir cleanup; se
reporta CleanupUncertain, nunca cancelación exitosa. Startup rechaza contenedores
pendientes por label, sin borrar recursos silenciosamente. Concurrencia por instancia.

## Review disposition by the principal

[Opus 5 High review](../reviews/M0-06-claude-opus-5.md) reported no false-positive
capability path and three P1 items. All resolved/verified before integration:

- P1-1: new seccomp-socket.json differs only by allowing socket. Applied JSON is
  verified for both profiles; both contents enter the configuration fingerprint.
  A regression test removes that single syscall and requires exact JSON equality.
  Controls remain bound to Network/Filesystem; tests reject every other pairing
  and verify that control profiles cannot weaken unrelated guarantees.
- P1-2: malformed guest evidence becomes empty failed evidence for that probe;
  report is degraded, retains every raw observation and lists invalid_evidence.
  Partial JSON is not trusted or salvaged. Infrastructure errors remain unavailable.
  Added regression and retained negative tests for malformed known events.
- P1-3: main.rs dispatches capabilities in a separate host argv branch that returns
  from main; stdio handlers never construct DockerGateway or call calibration.
  Six real CLI tests reject malformed invocations before Docker I/O. Existing MCP
  discovery/contract tests still expose exactly rust.project.open.

P2 decisions: added UNIX/NETLINK sockets; purpose labels are not counted as distinct
IP syscall tuples. Observation now records wall/output limits and memory bytes,
including 256MiB PID-probe exception; kernel reads retain actual CPU/PID/memory values.
OOM enforcement was demonstrated at 64MiB, not asserted experimentally at 256MiB.
No different image/configuration/scenario outside this closed vocabulary is approved.
`increased` checks errno0, and descendants/control evidence rejects truncation.
The duplicated event header dispatch intentionally handles unknown non-unit contents
that serde's adjacently-tagged unit Other rejects; a test pins this behavior. A
future variant must update that closed decoder. Keeping explicit event validation
fails closed; removing the header dispatch would reintroduce the observed parser bug.

Exit1 for both degraded/unavailable is intentional: JSON status is discriminated;
exit2 remains invalid usage. No public code change was made solely to distinguish
shell consumers who discard JSON. Unavailable omits unverified engine/identity/time
and observations; verified/degraded carry observed evidence. Report is unsigned and
never imported as authority. ioctl remains in the fixture profile; there is no TTY
or caller-selected program/input in this cut. Any future TTY/runtime expansion
requires security review. Startup reconciliation is conservative and per-instance;
operator must inspect labelled containers before explicit cleanup after host failure.

Final explicit gate rebuilt the updated static fixture, ran all four Docker tests
and the actual CLI: all ten capabilities true, invalid_evidence empty and project
code false. No unresolved P0/P1 accepted by the principal within this scope.
