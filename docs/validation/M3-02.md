# M3-02 — negotiated MCP Tasks path

Date: 2026-09-06. Status: **qualified; advertisement enabled**.

The application-owned `JobExecutor` is connected to all four M3 quality tools.
When the peer declares `io.modelcontextprotocol/tasks`, `auto` and `task` return
`CreateTaskResult`; `tasks/get` polls the owner-bound record, `tasks/cancel`
signals the registry-owned token, and terminal state is not published until joined
cleanup is observed. `RequestContext::ct` never controls a committed job. Unknown,
malformed, expired, revoked and foreign identifiers remain the same masked
`-32602 task unavailable` response without data or identifier echo.

`TASKS_ADVERTISEMENT_READY` is enabled after the product protocol matrix, live
Docker lifecycle, measured-budget series and stock-client gate passed. Inspector
2.5.0 declared Tasks and completed the task flow. Codex CLI/app-server 0.153.0 did
not declare Tasks, so it completed its supported synchronous/model-directed path
and cannot create, poll or cancel a task.

## Measured budgets

`M3-02-budgets.json` contains raw samples and phase values on the approved guest
image. Each candidate synchronous operation has 30 cold and 30 warm samples. The
nextest samples were carried forward from the current attempt log rather than
produced by the recorded run, as the receipt records; coverage and SemVer were
measured in the final assembly run.

| coverage / known-counts | 2,743 / 2,842 / 2,863 ms | 2,765 / 2,842 / 2,851 ms | Qualified for 60 s sync default; retain 120 s maximum. |

| mutation | task-only | task-only | No synchronous selection qualifies. |

Ancillary observations were a 262-byte creation response, 1,048-byte resident job
record, 0 ms observed poll latency, 1,088 ms cancellation-to-cleanup and 346 ms
EOF-to-join. ADR-060 explicitly reaffirms the 5 s seed, 300/3,600 s job, 60/240 s
cleanup, 2/5 s task-control, 30 s non-delivery, fixed 7,200,000 ms TTL, quota and
512 KiB response decisions from this evidence.
