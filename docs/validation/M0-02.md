## Entregable

`crates/domain` implementa los tipos y comportamientos de
[ADR-022](../adr/ADR-022-domain-contracts.md): identificadores validados, errores y
envelopes, diagnósticos/sugerencias, evaluación de freshness con Clock y validación
de evidencia al deserializar. No incluye un servidor MCP, registro/autorización de
proyectos, generación aleatoria, cálculo de hashes, persistencia o sandbox.

La verificación normal del grafo (`cargo tree -p rust-engineering-domain --edges
normal --locked --offline`) muestra solo Serde y sus dependencias de derive; no hay
adapters. serde_json solo aparece como dependencia de tests. Revisión del source
confirma ausencia de I/O/procesos/red/JSON-RPC y `serde_json::Value` en producción.
No existe todavía application: se añadirá con un use case consumidor real.

## Pruebas discriminantes

- `tests/contracts.rs`: formato canónico, paths/bytes inválidos, estados cerrados,
  nueve errores y mapping, cancelación, campos nullable requeridos, error parcial,
  status incompatible, E0502 como resultado normal y diagnóstico conservado.
- `tests/diagnostics.rs`: coordenadas cero/invertidas, Unicode/multilínea, ubicación
  ausente, rangos vacíos, bytes independientes, sugerencias multipartes/deleciones,
  campos desconocidos y validación anidada al deserializar.
- `tests/freshness.rs`: umbrales exactos, futuro/fecha ausente/overflow, importación
  que no rejuvenece el snapshot, red histórica que no implica live, policy inválida,
  evidencia parcial o modificada y roundtrip de un resultado snapshot tipado.
- Doctest: identidad y ejecución no se aceptan como el mismo tipo Rust.

Los tests del dominio ejecutan unidades puras mediante su API pública desde tests
de integración; no se atribuye a estos tests seguridad de filesystem o procesos.
Los estados calculados son coherentes con los inputs declarados, no autentican su
procedencia. Deserializar no sustituye reevaluar frente al reloj actual.
