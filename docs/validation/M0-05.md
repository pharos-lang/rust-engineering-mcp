## Alcance entregado

ADR-025 acota esta vertical a escenarios sintéticos cerrados en una imagen local
inmutable. Tipos domain → ExecutionPort application → DockerGateway → supervisor.
Sin argv/cwd/imagen del peer, shells, binds de host, Cargo ni descargas implícitas.
Rootfs read-only, tmpfs acotados, PID namespace privado por defecto Docker,
seccomp allowlist sin sockets y recursos explícitos. No anuncia tiers todavía.
El único spawn de producto está en supervisor.rs. El fingerprint incluye imagen,
identidad de engine, hash de cliente Docker, escenario/límites y perfil.

Timeout/cancelación/overflow matan el cliente attach, eliminan el contenedor y
verifican ausencia por nombre exacto. Un fallo de cleanup es CleanupUncertain y
bloquea esa instancia. Un daemon/host fallido no permite asegurar terminación;
no hay recuperación persistente de contenedores al reiniciar el gateway.
El host debe resolver una limpieza incierta antes de reintentar en otra instancia.
Preparación/inspección/cleanup tienen presupuestos separados de hasta 10s por
operación; wall_ms mide la fase attach/ejecución, no el tiempo total del caso de uso.
El host protege binario, socket y state root; la validación de identidad detecta
reemplazos observados, no constituye resistencia universal a rename-ABA del host.

El gate Docker construye fixture Go 1.27.1 Linux arm64 estático y una imagen FROM
scratch con --pull=false/--network=none. Go solo es herramienta de desarrollo;
no se incorpora como dependencia Rust. La imagen queda local para reproducibilidad.
El script no instala herramientas ni inicia Docker. Incluye buildx ya instalado
mediante una configuración temporal sin credenciales. Cargo usa locked/offline.

Pruebas reales: éxito/exit7 como resultados normales, fingerprint estable y
sensible al escenario, timeout con grandchild doble fork/setsid huérfano adoptado
por PID1, cancelación, stdout+stderr concurrentes limitados, limpieza y recuperación.
Pruebas adicionales: límites inválidos, configuración inválida antes de I/O,
root de control reemplazada, cada capability requerida ausente y opt-in/tier.
El gate portable omite explícitamente las tres pruebas Docker; no cuentan como
acreditadas sin ejecutar el gate explícito. No hay evidencia Linux/Windows nativos.
Cargo audit local: 152 dependencias, cero vulnerabilidades/warnings. Cargo deny
instalado pero sin policy: no ejecutado. No se ha instalado Rust Linux distinto.

  fingerprint separately. Tests mutate argument vectors; real repeated runs agree.
- P1-2: SandboxEvidence carries configuration_fingerprint; admission compares the
  expected configuration and rejects mismatch. Added discriminating mismatch test.
- P2-3: restart_syscall and clock_getres allowed. mremap deferred until an approved
  runtime requires it; no speculative M1 syscall expansion.
- P2-4: applied config verified after create and before start, including CapAdd,
  inherited volumes, security profile and every enforced resource flag.
- P2-5: startup refuses any existing gateway-labelled container. No automatic sweep
  of host state or unrelated instances. Stale private control dirs require explicit
  owner cleanup, documented; no claim of crash-time cleanup. Fixture lifetimes are
  bounded to 60s, contrary to the review's indefinite-lifetime assumption.
- P2-6: supervisor duration and total gateway duration now separate.
- P2-7: state-root uid and permissions enforced; root and directory identity checked.
  CLI path access remains trusted-host TCB; applied seccomp content is verified.
- P2-8: None does not satisfy the external-process sandbox predicate.
- P3: Busy distinct; poison quarantines; client hash rechecked; /work exec documented;
  readers made nonblocking and joined; XNU errno meaning documented. Invalid installs
  remain InvalidConfiguration. Retain EPERM deny-default and unsupported ABI aliases:
  no M1 runtime compatibility promised and no unverified ENOSYS fallback expansion.
- Additional principal fix: UTF-8 replacement cannot inflate returned text above

Sol High independent read-only check found no P0/P1/P2 in the original bounded

### Follow-up and principal disposition

Opus 5 Medium closed P1-1/P1-2, confirmed reader cleanup and raised two new P1s.
The principal resolved both before merge:

- Created-but-never-started containers cannot be exit0: State.Status must be exited,
  StartedAt nonzero, Error empty, stopped/Pid0 and CLI code equal to process code.
  Unit test distinguishes created/error states and normal exit7. Requiring CLI0
  was rejected because Docker attach correctly propagates exit7 (real test).
- Runtime explicitly runc, daemon DefaultRuntime identity recorded/rechecked,
  HostConfig.Runtime verified. Init=false explicit; default masked/readonly proc
  paths, no custom ulimits/sysctls/userns/cgroup parent and applied label checked.
  Each altered applied setting is covered by mutation tests.
- restart_syscall is present in the committed seccomp file; the follow-up packet
  omitted that file, so closure is principal source verification, not Claude approval.
- Output budget documented per stream. Mutex admission is per instance, not a
  cross-process lock; a trusted host controls its instance concurrency. Startup
  label reconciliation is conservative detection, not global mutual exclusion.

Final gate: fmt/check/clippy/test/doctest passed. 115 portable tests + 3 explicit
Docker tests + 1 doctest = 119. Local audit: 152 dependencies, zero vulnerabilities.
No unresolved P0/P1 accepted by the principal in this bounded probe scope.
