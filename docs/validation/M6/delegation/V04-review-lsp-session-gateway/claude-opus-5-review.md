# Review — M6 analyzer vertical (execution adapter, capture, calibration, gate)

## Verdict

**Block** — on four P2 findings. None is a containment hole: goal 1 (lifecycle/containment) holds as far as the diff can establish it, and I found no path on which the docker child or the guest container outlives `busy`. The block is on (a) one product-path defect in the completeness/omission pairing, (b) a calibration oracle that cannot observe the thing it asserts, (c) a receipt that can present a previous run's passes as this run's, and (d) an admission widening that no ADR in the diff records. All four are local fixes.

## What I verified

**Goal 1 (lifecycle/containment) — no finding above P3.** `ChildGuard` kills and reaps in `Drop`, and every `?` in `LspSession::open` after `command.spawn()` unwinds through it (`stdin.take().ok_or(…)?`, `nonblocking(&stdin)?`). `close` consumes `self`, so the guard runs even after `wait_for_exit` has already reaped (std's `Child::kill` is a no-op once a status is cached, so there is no recycled-PID kill). `fail()` takes `stdin` and kills on every terminal error; `close()` takes `stdin` after the `exit` notification and before `wait_for_exit`, so the peer gets EOF exactly once and at the right moment. EPIPE/`Ok(0)` on write → `Io` → fatal; `WouldBlock`/`Interrupted` → retry with `guard()` in between; partial writes are resumed from `self.written`. `guard()` checks cancellation **before** the deadline (so a cancelled call is never a timeout), and it is called on every iteration of `send`, `recv_until` and therefore `next_event_until`/`request`; `until()` is `Instant::now().checked_add(timeout).map_or(deadline, |u| u.min(deadline))` — no overflow, no negative durations, never extendable past the session deadline. The only unslept loop is when `step()` reports progress, which is bounded by `READ_BUDGET` per pipe per pass and by the 16 MiB stdout budget. `inbox`, `status_transcript` and `server_requests` are all bounded transitively by the decoder's 4096-message and 16 MiB limits. In `execute_bounded` there is **no return between volume creation and `cleanup_analyzer`** — all of it is inside the closure, `terminal`/cleanup run before `work?`, and `_busy` drops after; `probe()` has the same shape. The docker CLI child is joined inside `converse` (via `close`) *before* `cleanup_analyzer` runs, and the container's own kill/rm/absence is `cleanup_inner`'s job, as the module header states.

**Goal 2 (limits before allocation).** `read_stdout` charges `bytes_in` and fails on `ByteLimit` **before** `decoder.feed`; `read_stderr` and `drain_quietly` compute `room = max_stderr.saturating_sub(kept.len())` and `keep = room.min(count)` before `extend_from_slice`, so `stderr_kept` never exceeds the bound while `stderr_len` counts everything and `stderr_truncated` records the gap. No method exposes the stderr bytes; `summary()` publishes only `stderr_len`, the digest and the flag. `server_requests: Vec<String>` holds peer-supplied method names, and `summary()` reduces it to `bounded_count(len)` — the strings are dropped, so no peer text reaches a result. `convert`'s `CodeActions` arm bounds `visible = total.min(MAX_ACTIONS)` before `take(visible)`, and `total - visible` cannot underflow. `send` allocates the encoded frame before checking `max_frame_bytes`, but the input is this module's own bounded document. **Not verifiable from the diff:** whether `lsp_codec::Decoder` bounds what it *buffers* (not just what it parses) — `Decoder`, `DecoderLimits` and `Correlator` are pre-existing and unmodified here, so the `MalformedHeader`-for-oversized-`Content-Length` claim rests on code outside this diff.

**Goal 3 (admission/identity) — one P2, above.** `execute_bounded` and `probe` both refuse a non-M6 `image_id` before `hold_busy`, before the volume and before any container; `execute_bounded` additionally refuses a quarantined, calibrating or unverified gateway. No new `test-hooks` feature and no production env-var bypass: `probe`, `container_top`, `AnalyzerBudgets::with_initialize` and the whole `analyzer_native` module are `#[cfg(test)]`, and `RUST_MCP_TEST_IMAGE` is read only there and refuses anything but the admitted digest. The version and binary sha256 are **pinned constants**, not probed per call; the only assertions that they describe the real binary are the `#[ignore]`d m6-01 cut and the host-side cross-check in `pinned_analyzer_identity()`, both `full`-gate-only — there is no ordinary unit test tying `ANALYZER_VERSION`/`ANALYZER_BINARY_SHA256` to `docs/validation/M6/provisioning.json`. I could not check `set_verified` (used by `Session::open` to skip base calibration); if it is not `#[cfg(test)]`, it is a production bypass of the `verified` gate.

**Goal 4 (capture-time rejection) — one P3, above.** `analyzer_config_name` is applied to the **entry name** in the directory walk, before `kind == FileType::Directory` and before any `open_path`, so it covers directories, symlinks and any other object kind, at any depth, case-insensitively and dot-prefixed; the `file()` path repeats it on `path.file_name()`. Prefix matches (`rust-analyzer.toml.bak`) are correctly *not* refused, and the tests cover all of this. An excluded directory (`target`, `.git`) is never captured, so a `rust-analyzer.toml` under one cannot reach the bundle either way; the same holds for anything dropped at a depth limit.

**Goal 5 (applied container shape).** `Phase::Analyzer` gets `--entrypoint=/opt/analyzer/bin/rust-analyzer` with an empty argument list, `/source` mounted `,readonly` (because `ingesting()` is false), and `--interactive` — no `--tty`, so no tty semantics leak, and `docker container start --attach --interactive` attaches stdout and stderr as separate streams. `Phase::interactive() = ingesting() || Analyzer` is behaviourally identical to `ingesting()` for every pre-existing phase, so the `rust_applied::verify` and `run_started_container` call-site changes are regression-free. The new phases are added to the `verify_arguments` self-check enumeration. **Not verifiable from the diff:** the rest of the flag set (read-only rootfs, `--network=none`, cap-drop, no-new-privileges, pids/cpus/memory, seccomp, `--user 65534`, tmpfs sizes) comes from the unshown body of `arguments()`, and `rust_applied`'s applied-environment comparison is not in the diff — if that comparison is a literal list rather than derived from `Phase::environment()`, the newly pushed `RA_LOG=error` will fail verification at runtime (loudly, with cleanup, not silently).

**Goal 6 (calibration oracles) — two P2s and three P3s, above.** What holds: `clean()` uses the label inventory (`--all` for containers) rather than a name, so it cannot inspect the wrong object; m6-03 requires `samples >= MIN_PROGRAM_SAMPLES && !programs.is_empty()`, so an empty sample set cannot pass; m6-05 asserts `NotReady`, which `classify(Timeout, Stage::Initialize) = TimeoutInitialize` cannot satisfy, so the never-ready cut cannot pass by timing out on `initialize` — and it proves the lock was released by running a second `probe` afterwards; m6-07 asserts `evidence["killed"] == true`, so a kill that never landed or landed after the answer fails loudly rather than passing; m6-01 publishes its failing cut document *before* raising, with a reproducible command in the note. The gate driver stops on the first failure, and `passed` requires `"test result: ok. 1 passed; 0 failed; 0 ignored;"` — a filtered-out selection cannot be recorded as a pass. One unmeasured side effect worth knowing: `ProgramObserver::is_cancelled` performs 2–3 blocking Docker round trips from inside the session's hot loop, so the timings recorded in the m6-03 receipt (`quiescent_after_ms`, `session`) are inflated by the observation and are not comparable with the other cuts.

**Goal 7 (Python) — one P3, above.** No `shell=True`, no `argv`-derived paths, no `/tmp` literals; `Popen` takes a list, `start_new_session=True` makes `os.killpg(process.pid, SIGKILL)` correct, the receipt starts at `"running"` and reaches `"passed"` only after the native receipt is validated, `except BaseException` records the error before re-raising, `finally` always saves, and the post-run source re-hash turns a vanished input into a recorded failure rather than a traceback. The three digest cross-checks (`analyzer_gateway.rs`, ADR-085's single `**Digest admitido:**` line, `provisioning.json`) all match the strings actually present in the diff, and the gate refuses rather than preferring one. `MODULE = NATIVE_SOURCE.stem` resolves to `analyzer_native`, which is the correct `--exact` path for a `#[cfg(test)] mod` of the lib, and `ignored_tests` correctly matches only the nine column-0 `#[test] #[ignore]` functions (the indented `mod unit` tests are excluded). The `docs/ci.md` count is internally consistent (25 core + 14 native + `m5-runtime` + `m6-runtime` = 41).
