# Review: M6 rust-analyzer/rust-src provisioning

## Verdict

**Block** — no exploitable extraction/network/receipt-forgery bug found, but two P2 issues should be fixed before merge: (1) `provision.py`'s own CLI entry point does not apply the project's established `beside_default` taint-safe pattern to an argv path that flows into `shutil.rmtree()`, likely failing the same S2083/S8707 rule this PR is designed to satisfy elsewhere; (2) the tar-member guard's most security-relevant branches (hardlink, device, fifo, duplicate member) have zero discriminating test coverage — those specific `raise` clauses could be deleted and the full test suite would still pass, which is exactly the failure mode goal 4 asked me to check for.

## What I verified

- Traced the full acquisition path in `provision.py`: `fetch_url` host-prefix check → `ensure_downloaded` (atomic write, hash verified on both cache-hit and fresh-download paths) → `validate_component_archive` (absolute path, `..`, backslash, non-allowlisted characters, wrong archive root, duplicate names, symlink/hardlink/dev/fifo, empty-archive all rejected) → copy into build context → `SHA256SUMS` written and `docker build --network=none --pull=false --no-cache` invoked, with `build.sh` re-checking `sha256sum --check SHA256SUMS` before extracting anything.
- Confirmed the symlink fix (`/opt/analyzer/lib/*.so → /opt/rust/lib/*.so`) only republishes files already present in the same image filesystem and does not touch `PATH`, `LD_LIBRARY_PATH`, or `ldconfig`.
- Confirmed the "off PATH" claim is authoritatively checked with `command -v rust-analyzer` inside the real container `PATH` (not a hardcoded directory list) in `scripts/build-m6-runtime.py`, and that `evaluate_status` is a pure AND over five guest-observed booleans, each individually falsified by a dedicated test in `scripts/test-m6-provisioning.py::EvaluateStatusTests`.
- Confirmed `beside_default` correctly reduces any CLI value to its basename beside the fixed default directory, and is tested against a traversal payload (`../../../etc/passwd`) in `test-m6-provisioning.py::BesideDefaultTests` — but is not applied to `provision.py`'s own `--output` argument (P2 above).
- Cross-checked `BASE_IMAGE_ID`/digest across `provision.py`, `build-m6-runtime.py`, `Dockerfile`, and `ADR-082` — identical value in all four.
- Cross-checked `docs/ci.md` stage names/counts against the two new `run(...)` lines in `scripts/gate.py` and the two new coverage invocations in `.github/workflows/sonarcloud.yml` — consistent.
