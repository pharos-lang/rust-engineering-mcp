# M6-04 / M6-05 — code actions y `rust.analyzer.action.apply` por el writer M2

Estado: **Done local**, 2026-09-12. Rama `ai/m6-analyzer`. Cortes M6-04
(actions → `WorkspaceEdit` validado → `MutationCandidate` M2 con diff previo) y
M6-05 (`action.apply` por el único writer M2). Inventario público: **36 tools**
(las 34 anteriores byte-idénticas). Postcondición **Opción A** (owner,
2026-09-12): validación estructural + diff de preview + plan ligado a la

**no está compile-verificada** y el llamador debe correr `rust.check` después.

## Evidencia de producto: el ciclo `preview→commit→receipt` de extremo a extremo

El writer M2 corre en el host (macOS), no en el guest, así que el camino de
escritura se acredita con los tres tests de extremo a extremo de
`crates/mcp-server/tests/analyzer_runtime.rs`, **ejecutados por el orquestador**
contra la imagen real (`sha256:f39a5b33…`), 57,2 s el 2026-09-12T23:2x:
`analyzer_runtime` sigue desgateado del `m6-runtime` (flake de arnés de M6-01,
deuda W05f), por lo que esta es evidencia de orquestador, no del gate:

| Test | Qué acredita |
| --- | --- |
| `analyzer_actions_list_…` | `rust.analyzer.actions` lista ≥1 acción aplicable con su `action_digest`; el disco no cambia |
| `analyzer_action_apply_commits_through_the_writer_…` | `preview` no toca el disco; `commit` por el writer M2 **cambia los bytes de `src/lib.rs`** al texto editado (receipt `effect_after == intended_after`), y el `project_ref` precommit queda invalidado (una segunda llamada falla; tras reabrir, el receipt es `committed`) |
| `analyzer_action_apply_is_action_stale_after_a_source_change_…` | un cambio externo de la fuente entre `preview` y `commit` produce `blocked/ACTION_STALE`, el writer **nunca** se llama, y el disco conserva el cambio externo |

Los tests de ciclo de vida sin Docker (registro macOS real + puerto y writer
falsos) prueban además: `CONFLICT` con digest erróneo, `commit` que llega al
writer exactamente una vez, receipt `PERMISSION_DENIED` sobre el `project_ref`
viejo, `ACTION_STALE` en preview y commit, y el rechazo de un plan de otro kind
(en ambas direcciones, a nivel de store).

## Límites y deuda

- **No compile-verificado** (Opción A): el diff exacto es la superficie de
  revisión; una code action puede reescribir hasta 128 archivos `.rs`
  capturados (incl. `build.rs`/vendorizados). El llamador corre `rust.check`.
- Los quickfixes ligados a diagnósticos no aparecen bajo la config mínima
  (experimental diagnostics off, Opción A de M6-03); sí los assists de
  refactor basados en AST, que es lo que M6-04/05 aplican.
- Deuda M6-06: precisión de `admitted` en el audit tras denegaciones
  post-grant; un flag por archivo (generado/vendorizado) en los datos del
  preview; re-gatear `analyzer_runtime` (deuda W05f).
