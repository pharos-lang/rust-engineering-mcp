# Review: `scripts/test-m5-clients.py` — Codex → Claude Code qualification client swap

## Verdict
**Block**

The flow-oracle scaffolding (`claude_items`, ordering/exactly-once checks, argument equality) is generally careful and mirrors the rigor of the prior Codex oracle. However, there are concrete gaps in exactly the three areas the review was asked to focus on — model-fallback acceptance, resource-content evidence integrity, and un-scrubbed raw evidence staging — plus one likely-brittle exact-equality check that risks failing every legitimate run. These should be fixed before this replaces the Codex closure.

## Findings

| Severity | File:line / function | Finding | Evidence from the diff | 
|---|---|---|---|
| P1 | `validate_claude_session` (test-m5-clients.py) | The oracle never checks *which* model produced each `tool_use` block. It only checks that `init.model == CLAUDE_MODEL` and that `CLAUDE_MODEL` is *a* key in `final.modelUsage`. A session where a fallback/sub-agent model issues all the actual tool calls while `claude-sonnet-5` contributes only a trivial final message would still pass. | `claude_item()`/`claude_items()` never capture `message.get("model")` from the assistant event that contains each `tool_use` block (only `id`, `name`, `input` are kept). `validate_claude_session` only does `if CLAUDE_MODEL not in usage: raise ...`, and the fixture itself demonstrates two co-existing models are accepted: `modelUsage": {"claude-haiku-4-5-20251001": {}, "claude-sonnet-5": {}}` → `session["observed_models"] == ["claude-haiku-4-5-20251001", "claude-sonnet-5"]` is asserted as *passing*. | 
| P1 | `validate_model_resource_read` / `validate_runtime_model_flow` | The "native read of that artifact as a Resource" step is checked only by URI string equality and presence of a non-empty `text`/`blob`; the returned bytes are never compared against the artifact's own recorded `sha256` (captured earlier from `check_runtime_observation`'s `artifacts[].sha256`). The receipt field named for this is `resource_uri_sha256`, which hashes the URI text, not the fetched content. This overstates what was verified: a resource read that returns the right URI but arbitrary/garbage `blob` content would still pass. | `resource = block.get("resource"); ... or not any(isinstance(resource.get(key), str) and resource[key] for key in ("text","blob")): raise ...` — no comparison to `artifact["sha256"]`. `facts["resource_uri_sha256"] = load_m3().digest(resource_uri.encode())` hashes the URI, not the blob. |
| P1 | `claude_gate` (evidence staging) | Raw, unfiltered Claude CLI `stdout`/`stderr` are written verbatim into the attempt directory with no visible credential-shaped-content scrub, unlike the old Codex path which only persisted individually-typed RPC events via `m3.append_observation`. If the CLI ever echoes auth/debug material to stderr (e.g., on an auth edge case), it lands under `docs/validation/M5/clients/...`. | `events_path.write_bytes(outcome["stdout"]); stderr_path.write_bytes(outcome["stderr"])` — no call to `assert_no_credentials` (which is in the `m3_reuse` inventory) is visible anywhere in `claude_gate`. |
| P2 | `validate_claude_session` | `init.get("mcp_servers") != [{"name": CLAUDE_SERVER, "status": "connected"}]` is a hard, exact-equality check against a two-key dict. Real Claude Code `system/init` events commonly carry additional per-server metadata (type/tools/etc.). If the real shape has any extra key, this check fails on every genuine run, not just malicious ones — a strict-but-brittle oracle risks becoming a strict-but-*always-red* oracle, which invites loosening it later under time pressure. | `if init.get("mcp_servers") != [{"name": CLAUDE_SERVER, "status": "connected"}]: raise RuntimeError(...)`; the unit fixture `init()` only ever produces that exact two-key shape, so the assumption is untested against a richer real shape. |
| P2 | `claude_gate` return value | `"credentials_copied": False` and `"session_persistence": False` are hardcoded literals asserted into the receipt, not derived from any runtime check (e.g., scanning `private` for stray credential files before `rmtree`, or confirming no session artifact was written). This is an evidence-integrity concern: the receipt states a security property as fact without verifying it, unlike the old symlink-based Codex approach which had a structurally-enforced (not just claimed) no-copy guarantee. | `return {... "credentials_copied": False, "session_persistence": False, ...}` — no corresponding check anywhere in `claude_gate`/`run_claude`. |
| P2 | `claude_environment` | The real `HOME` is passed through unmodified to the Claude subprocess (only `PATH`/`TMPDIR`/`LANG`/`MCP_TOOL_TIMEOUT` are overridden, plus `USER`/`LOGNAME`/`SHELL` passthrough). This is broader than the "read login in place, never copy" goal requires — the whole account home tree is reachable by the child, and safety currently depends entirely on `--restricted`/`--tools`/`--allowedTools` doing their job correctly, with no independent verification beyond the `tools`/`mcp_servers` fields in `init`. The prior Codex gate instead isolated only the single needed credential file via a private-`CODEX_HOME` symlink. | `environment = {"HOME": os.environ["HOME"], "PATH": "...", "TMPDIR": str(private / "tmp"), ...}` vs. the removed `private = tempfile.mkdtemp(...); os.symlink(auth, private / "auth.json"); os.environ["CODEX_HOME"] = str(private)` pattern. |
| P3 | `claude_gate` → `mcp.json` | `{"mcpServers": {CLAUDE_SERVER: {"command": proxy[0], "args": proxy[1:], "env": {}}}}` sets `env` to an empty dict. Depending on how Claude Code populates the spawned MCP server's environment from this field (merge vs. replace), the proxied `rust-engineering-mcp` process could be started with no `PATH`/`HOME`/locale at all, which is a plausible source of flaky failures unrelated to what's being qualified. Not verifiable from the diff alone. | `"env": {}` in the written `config`. |
| P3 | `opened_references` / `validate_docker_free_model_flow` | Nothing bounds the model to opening *only* the roots required by the plan — any path present in `FIXTURES` is accepted once. This is lenient (allows extraneous, unneeded root opens without failing) though it doesn't create a forgeability risk since each individually required tool call is still checked against its bound root. | `roots = {str(ROOT / path): name for name, path in FIXTURES.items()}` is the whole `FIXTURES` map, not restricted to the roots referenced by `positive` rows. |
| P3 | `MCP_TOOL_TIMEOUT_MS` vs. docker-free overall timeout | `MCP_TOOL_TIMEOUT_MS = 900_000` (15 min per MCP tool call) is set globally, but the docker-free `claude_gate` invocation uses an overall wall-clock timeout of `900` seconds (`claude_gate(attempt, DOCKER_FREE, free_argv, plan, 900)`), i.e., exactly one tool-call's worth of budget for the whole session. Harmless in practice (docker-free calls are fast declared refusals) but an inconsistent constant. | `"mcp_tool_timeout_ms": MCP_TOOL_TIMEOUT_MS` vs. `receipt["claude_code"] = {DOCKER_FREE: claude_gate(attempt, DOCKER_FREE, free_argv, plan, 900)}`. |
| P3 | `claude_structured_payload` | Relies on the empirical claim that Claude relays the raw server JSON verbatim in `content` even for `isError` results (no `"Error: "` prefix in `content`, only in `tool_use_result`, per the unit fixture). If real Claude ever prefixes error `content` text, every negative-path parse silently returns `None` and the flow oracle fails closed with an opaque "carried no structured result" — not a security bug, but worth flagging as an unverified assumption baked into the parser. | `ClaudeTranscriptTests.transcript()`: `self.result("t3", refused, is_error=True, structured="Error: " + refused)` — the raw JSON, not the `"Error: "`-prefixed string, is what's parsed. |

## What I verified
- Exactly-once / no-retry enforcement: `claude_items` requires a strict 1:1 bijection between `tool_use` ids and `tool_result` ids (`set(results) != set(by_id)`), rejects duplicate `tool_use` ids, and both flow validators (`validate_docker_free_model_flow`, `validate_runtime_model_flow`) reject retried, omitted, or reordered calls (unit tests exercise all of these: retried tool, omitted tool, foreign capability, unknown tool suffix, wrong arguments, undeclared result, opening before use, out-of-order open, out-of-order comparisons).
- Argument binding: each of the four refusal calls and both benchmark runs is checked by *exact* dict equality against `{"project_ref": <opened ref>, **row["arguments"]}`, catching both missing and injected keys.
- Resource-read binding to the *exact* session-issued URI (not just any resource, and not the wrong artifact from the same run) is enforced and unit-tested (`did not match the issued artifact`, `another artifact`).
- Ordering: the runtime flow's `positions` list enforces a strict monotonic order across open → discover → run×2 → compare×2 → read, and is unit-tested for a late reordered open.
- Removal of Codex is consistent: `CONTROLLER`/`CODEX_VERSION`/`codex_app_server` are removed from `source_hashes`, `client_versions`, `preconditions`, `CALL_CLIENTS`, and the corresponding unit tests (`source_sha256` set, `clients["claude_code"]`, foreign-client rejection using `"claude-code"`) are updated in lockstep — no leftover Codex plumbing spotted.
- No-Docker-socket invariant (`docker_free_socket_created`) is preserved unchanged across the client swap.
- `claude_logged_in()` reads status via `claude auth status` (no file copy) and the symlink-based `CODEX_HOME` credential isolation is gone (see P2 HOME finding above) rather than replaced by an equivalent narrow isolation.
- I did not find a way to fabricate a "passed" runtime/docker-free receipt using only forgeable shapes accepted by the checks above (aside from the model-attribution and resource-content gaps called out as P1).
