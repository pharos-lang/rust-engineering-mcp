# Evidencia M0-08 — SQLite catalog foundation

Fecha: 2026-09-03. Base main 2cadf51, rama ai/m0-08-sqlite-catalog.
Rust/Cargo 1.98.1, macOS ARM64. rusqlite 0.40.2, bundled SQLite 3.53.2
(header del paquete libsqlite3-sys 0.38.2 y FTS5 real verificados).

Vertical: tests de integración → search_catalog/application → CatalogRepository →
SQLite real → facts tipados y SnapshotEvidence reevaluada con Clock. No nuevas tools
MCP. Schema v1 normaliza crates/versions/features/dependencies/advisories y metadata
de snapshot. Provenance se conserva como JSON tipado validado en el singleton del
snapshot; freshness se calcula al consultar, no se copia como una etiqueta vigente.

El formato payload es una imagen SQLite con manifest v1, sequence, tamaño y SHA256.
Checksum se verifica contra expectativa del host; no demuestra firma ni publisher.
Adquisición filesystem, archivos de distribución firmados y CLI permanecen M1-10.
El runtime del adapter no abre archivos: SQLite deserializa bytes en memoria y la
conexión final usa READONLY/query_only, temp_store=MEMORY, ATTACH=0, sin triggers,
vistas, extensiones o SQL del caller. Se conservan controles defensive/trusted schema.

Migración desde DB vacía v0 → v1: DDL, checksum ledger y user_version en una misma
transacción; idempotente en v1, falla cerrado ante versiones futuras o ledger alterado.
Activación requiere sequence estrictamente creciente y reemplaza toda la conexión
con metadata después de validar staging; &mut serializa acceso y no retiene lectores
antiguos. FTS5 se reconstruye determinísticamente desde facts y verifica integridad
contra su contenido externo. Validación de esquema compara el SQL exacto con una DB
recién construida con la misma versión fijada, incluidos shadow tables e índices.

Presupuestos: image64MiB, 1000crates, 64versions/crate, 128features/deps/advisories
por versión, 100000entradas agregadas, query256bytes/16terms/50results. SQLite aplica
límites adicionales y progress handler (10000000opcodes o30s por operación). Estos
límites no son aislamiento OS ni un hard cap global de memoria nativa. Las queries
FTS se convierten en términos literales; filtros híbridos y paginación son M1.

Quince tests reales: migración rollback/idempotencia, importaciones rehasheadas con
DDL inesperado, trigger/view, FK huérfana, FTS desactualizado, semver/timestamp/provenance
inválidos; readonly/ATTACH/progress; roundtrip completo de facts; freshness en umbrales;
FTS ante sintaxis adversa; hash/size/WAL/version; failed activation/rollback; bytes
idénticos con entrada reordenada; reconstrucción de generación. Sin mocks SQLite.

cargo fmt --check

cargo clippy --workspace --all-targets --locked --offline -- -D warnings

147 tests + 1 doctest passed; 4 tests Docker fuera de este gate proporcional,
pendientes de repetir en M0-12. Audit160dependencies: cero vulnerabilidades y warnings.
Dos ejecuciones tras añadir exports encontraron metadata incremental obsoleta,
aunque builds focalizados y Clippy veían los tipos nuevos. Una limpieza focalizada
permitió el primer gate; el gate final ejecuta CARGO_INCREMENTAL=0 y recompila sin
esa cache. No se cambiaron toolchain ni contratos para eludir errores. Esta variable
debe conservarse en la reproducción del gate y en CI local.
