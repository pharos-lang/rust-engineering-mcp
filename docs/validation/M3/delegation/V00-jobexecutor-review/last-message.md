## 1. Verdict

**Revise.**

The core authority and containment invariants of ADR-060 hold in this package: the job permit is genuinely the ADR-030 semaphore slot; `status`/`cancel`/`update` never touch it; `Cancelled` is reachable **only** through an `Observed` signal (`finish` requires both the caller's `CleanupObservation::Observed` *and* `signal.cleanup_observed()`; `finalize_joined_cleanup` re-checks); the permit is released only from `release_and_event`, which is reachable only from those two guarded paths; delivery is marked strictly after `Ok(Ok(()))` send completion without altering ADR-030 lease retention; `shutdown_and_join` is awaited inside the `block_on` closure before `workers.shutdown(grace)` and `shutdown_timeout`; TTL is a fixed non-null constant that polling cannot slide; retention quotas reject and never evict; domain/application carry only `serde`/domain dependencies (no tokio, no rmcp); and no `unwrap`/`expect`/`panic` sits on a normal path.

What blocks acceptance is one publication-correctness defect (a successful job whose cleanup outlives the work budget is published as `failed`/`timed_out`, discarding the real result), plus a set of contract gaps and two tests that cannot fail and are credited against D06-T03 and D06-T06.

## 4. Contradictions with ADR-060/ADR-030/existing code

1. **Work budget vs. cleanup exclusion** (V00-01/V00-02): the budget table excludes cleanup from async work, but `watchdog` enforces `work_deadline` on records in `Cleanup`.
2. **“The job permit *is* the `run_joined` permit”** (V00-03): delivered as a second acquisition of the same one-slot semaphore, with no path for the job to run its own joined work.
3. **Terminal-state mapping** (V00-01): “a late successful operation after a cancellation request remains `Completed`” is satisfied for `ClientCancellation` but violated for `Deadline`, which unconditionally rewrites the completion.
4. **Task-control budget row (2 s / 5 s)**: unimplemented (V00-06).
5. **Artifact members projected `Unavailable` at read time**: unimplemented (V00-13).
6. **Owner binding definition**: the ADR specifies a derivation; the code ships an unconstrained newtype (V00-12).
7. Non-contradictions worth recording: `admission.rs` adds only a per-request `DeliveryToken` and a `mark_delivered` call on successful send — lease acquisition, tombstone retention, duplicate-ID closure and the 16-slot policy are untouched, so ADR-030 behaviour is preserved; `TASKS_ADVERTISEMENT_READY = false` plus `protocol.rs:1701` keep the capability and `rust.test.nextest` correctly dormant.

## 5. Missing tests

- **D06-T03**: no discriminating MCP-level masking test (V00-04); no case where one record is authorized and a sibling is not, proving per-record masking rather than a global switch. The fixture `JobAuthority` ignores `ProjectRef` entirely, so the cross-ProjectRef cell is untested.
- **D06-T06**: no real proof that `RequestContext::ct` cannot reach the job token (V00-05); no test of cancellation racing the commit point (roll-back-before-commit branch).
- **D06-T05**: cancel *during publication* and *during cleanup* are not exercised; only cancel-before-start and cancel-while-`Capture`.
- **D06-T09**: no just-*under* 5 s seed-commit case (only exact 5 000 ms, which `reached` treats as expired); no task-control 2 s/5 s cases; “poll does not extend TTL” is asserted by comparing `ttl_ms` before/after, which is a compile-time constant in `JobRecord::status` and therefore cannot fail.
- **D06-T11**: no exact-512-KiB / one-byte-over serialization test (V00-07); no test that a `finish` with uncertain cleanup holds the permit and does *not* publish (the CleanupUncertain branch of `finish` is never exercised).
- **D06-T07**: the adapter half (second `tools/call` and worker-backed Resource read returning busy/`SANDBOX_DENIED` while `tasks/*` stay responsive) is untested — expected for dormant code, but it is not yet evidence.
- **D06-T14**: `TracingJobEvents` output itself is never asserted; only the `JobEvent` struct is inspected, and two of its three assertions (`!contains("source")`, `!contains("argument")`) are structurally impossible to violate.
