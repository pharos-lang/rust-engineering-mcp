## Verdict: **Revise** (narrow — design and security core accepted; three contract-level gaps to close before Stage 1 qualification)

No P0/P1 survived verification. The handle-relative I/O, owner binding, publication ordering, chunk clamping and ArchiveBundle profile are correct, and the tests are genuinely discriminating (real digest/size/link/expiry oracles with positive controls, not tautologies). The findings below are quota-contract, ADR-conformance and robustness items.

### Focus items I verified as **correct**

- **No path-based `std::fs` on the state root.** Every effect goes through `openat`/`renameat`/`unlinkat`/`mkdirat` on a validated dirfd with `flags()` = `NOFOLLOW_ANY|RESOLVE_BENEATH` (`+O_UNIQUE` for files); `std::fs::File` is only ever built with `File::from(fd)`. Grep for `fs::{read,write,remove,rename,metadata,read_dir,OpenOptions,File::open}` in `crates/project-adapter/src` hits only pre-existing test code.
- **fallocate on APFS.** Confirmed in `rustix-1.1.4/src/backend/libc/fs/syscalls.rs:1787-1816`: the Apple path is `F_PREALLOCATE` **followed by `ftruncate(new_len)`**, so the blob really does become `member_cap_bytes` long. The accepted `size >= size_bytes` rule is safe: the surplus is `ftruncate`-extended (zero-filled, never stale disk data), `read_chunk` clamps `want = size_bytes.saturating_sub(offset).min(length)` (`quality.rs:995-1006`) and `digest_prefix` hashes exactly `size_bytes` (`quality.rs:662-681`). Positive control exists (`publishes_exact_bytes_and_serves_bounded_chunks`, tail read returns 1 000 bytes, `offset > size_bytes` → not found).
- **Ordering.** file `fsync`+`F_FULLFSYNC` → rename → destination-dir sync → source-dir sync, watermark advanced *before* the commit marker (`quality.rs:900-948`), truncation strictly after descriptor rename **and** descriptor-dir fsync. Both crash oracles are evidenced, including the "quarantine unless durable completion proven" row.
- **flock.** Exclusive non-blocking, `WOULDBLOCK → Busy`, never awaited; reads take no lock by decision (`quality.rs:251-262`, `read_chunk` comment at 970).
- **Free-space floor.** `reservation_fits` = `requested + 49 MiB + 16 MiB`, and 49 MiB is arithmetically identical to M2's `RECOVERY_STAGING_HEADROOM_BYTES (48 MiB) + RETAINED_METADATA_GROWTH_BYTES (128*8 KiB = 1 MiB)` in `mutation.rs:26-29`.
- **Owner binding.** Domain-separated prefix + 8-byte little-endian length prefix on every field including the workspace-root string; empty/oversized/NUL-bearing roots rejected (`quality.rs:687-709`). The collision test (`/a/bc` vs `/ab/c`) is a real positive control.
- **Uniform masking / TTL non-renewal / index bounds / 512 KiB cap.** Application maps every store error to `NotFound` and re-checks binding, job and row/cursor bounds; `encode_quality_chunk` rejects >320 KiB and >512 KiB serialized; the 436 908-byte base64 figure is asserted exactly.
- **M2 isolation.** Nothing outside the `rust-mcp-quality-artifacts-v1` fds is ever opened, listed or unlinked; the sibling-untouched assertion appears in both the quarantine and clock-regression tests.
- **`UtcInstant` calendar.** Hinnant `days_from_civil`/`civil_from_days` are transcribed correctly (I hand-checked 2100-03-01 in both directions — the century non-leap case). Round-trip re-rendering rejects `2026-02-30`, offsets, fractional seconds and non-canonical spellings; range is clamped to 1970–9999 so there is no 2038 or negative-year path. `unix_seconds()` is total and panic-free.
- **No new dependencies; layering clean.** `domain/Cargo.toml` = `serde` only, `project-adapter` gained nothing (`getrandom`, `sha2`, `rustix` were already there); `scripts/check-architecture.py:7,16-17` machine-enforces domain⊂{serde}, application⊂{domain}, no `std::fs`/`rmcp` in either. No `unwrap`/`expect`/`panic`/unchecked indexing in the new files (workspace denies all three anyway).

| F2 | P2 | `quality.rs:380-391` (`accounting`) | Expired descriptors are charged to owner/global quota unconditionally, and **nothing reclaims them automatically**: `reconcile` (`verify_pair`) never checks expiry, so an expired pair survives every restart, and `prune_expired` is only reachable from the (unwired) operator CLI. | After 128 MiB of expired evidence an owner is permanently rejected at admission with `QuotaExceeded`, and the global 256 MiB budget wedges, with no in-product way to reclaim. ### Contradictions with ADR-061 / ADR-060 / M2 code

1. **Shared primitive not applied to M2** — ADR-061 Decision: "Refactor **both** M2 `StateRoot` and the quality adapter onto it"; `mutation.rs`/`mutation_state.rs` are untouched, so `fixed_child` is a second copy of `prepare_mutation_state` that has already drifted (F1). Disclosed as open issue 3 in the delivery report.
2. **`M2_RECOVERY_HEADROOM_BYTES` is a mirrored literal** in `domain/src/quality_artifact.rs:628`; M2's `RECOVERY_HEADROOM_BYTES` is private in `mutation.rs:28`, so drift is silent at compile time. Only the `#[ignore]`d `native_apfs_quality_reservation_preserves_m2_headroom` couples them, empirically.
3. **`schemars`** — the ADR says the descriptor is "strict `serde`/`schemars` Rust data"; only `serde` + `deny_unknown_fields` is implemented. Domain has no `schemars` dependency at all, and descriptors never cross a tool-schema boundary, so this reads as an ADR wording issue rather than a defect — worth reconciling in the ADR.
4. **`quality-artifacts recover|prune` CLI** (ADR-061, M3-01) does not exist; `main.rs` still lists only `mutation list|prune`. This is what makes F2 unrecoverable in-product today.
5. **ADR-060 alignment is correct**: no `qjob_`/`qjr_` grammar was introduced; `QualityJobId = JobId` reuses the ADR-060 locator (`domain/src/job.rs:52-67`).
6. `mcp-server/src/stdio/resources.rs` is byte-identical M1 plus the pre-existing (I17/I17b) quality URI code; `with_quality_reader` is `#[allow(dead_code)]`, so no M1 semantics changed and nothing is wired.

### Missing tests (oracles I could not find)

- **No state-root mode fixture.** Every fixture forces `0o700` (`tests/quality_artifact_store.rs:80`), so F1 is invisible to the suite.
- **No symlink/FIFO/device planted inside `blob/` or `descriptor/`** — the `NOFOLLOW_ANY|O_UNIQUE` open path is only exercised through the hard-link case; the `NotPrivateRegularFile` quarantine reason has no test.
- **No expiry-vs-accounting test** — nothing asserts what an expired reservation or an expired descriptor does to the owner/global budget (F2/F3 would both have been caught).
- **"Two processes / no double accounting"** (ADR oracle row) is only half-covered: the ignored test proves busy-rejection and post-unlock admission, not that two processes see one global quota view.
- **`UtcInstant`** has no case at 2038+, at a non-leap century (`2100-02-29` must be rejected), or at the 9999 upper bound; the round-trip property covers 6 hand-picked seconds.
- **Duplicate `member_index`** paging (F4) untested.
- Disclosed and accepted by the author: non-macOS `UnsupportedPlatform` compiles but cannot execute here; the four content-parser rows (billion laughs, deep JSON, external-URI HTML, HTML script) and the guest-side `GuestArtifactEgress` symlink/device rejection belong to the egress/parser package.

### Limitations of this review

Read-only tools only — I did not compile, run any test, or check out the delivery report's SHA-256 values (no `sha256sum` available under this protocol), so "tests executed" claims are taken from the report and judged only by reading the test bodies. `rustix`'s Apple `fallocate` behaviour was verified from vendored source, not from a running `fstat`. The concurrency reasoning for two processes sharing a state root is by inspection of the lock scopes, not by execution. I reviewed the M2 `mutation.rs`/`mutation_state.rs` and `resources.rs` only where the new code touches them; the `nextest`/`tasks` files churning in this worktree (and the sibling test failures the report lists) are outside this package and were not assessed.
