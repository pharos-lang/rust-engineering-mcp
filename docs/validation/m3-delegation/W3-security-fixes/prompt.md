## Orchestrator dispositions — apply all of them

**V-SEC-01 (P1, fix now).** `crates/mcp-server/src/stdio/resources.rs` and `crates/mcp-server/src/stdio/quality_artifacts.rs` take a blocking `std::sync::Mutex::lock()` on the registry from the current-thread Tokio runtime, so a running job (which holds that lock on its blocking thread for up to the full job budget) freezes the event loop: no `tasks/get`, no `tasks/cancel`, no watchdog, no stdin/EOF. That inverts ADR-060's availability promise and removes the only cancellation channel while hostile code runs. Fix it: use a non-blocking acquisition on those paths and map contention to the existing masked outcome (`not_found` for the Resource read, `false`/`Unavailable` for the artifact-liveness projection), or route them through the worker admission that already returns busy. Add a regression test that holds the registry lock while a job runs and asserts that a `rust-quality-artifact://` read and a `tasks/get` both answer promptly instead of blocking.

**V-SEC-02 (P2, fix now).** Durable publication aborts the whole batch on the first per-member failure while leaving already-committed descriptors on disk, so the client never learns the locator and the orphaned bytes hold owner/global quota for the full TTL; and with `MEMBER_CAP = 256 KiB` plus the 128-entry archive charge, a realistic llvm-cov HTML report fails outright. Mirror Stage 0's behaviour: degrade per member (mark it omitted with an explicit flag, keep publishing the rest), and reconcile the aborted claim so nothing is retained unreachably. Raise the member cap toward ADR-061's 32 MiB per artifact and decide explicitly, in code and in `docs/tools.md`, how an HTML bundle with more entries than the per-job member charge allows is represented (a single bundle counted once is the natural answer — say what you choose). Prove it with a fixture whose HTML report is large enough to have exercised the old failure.

**V-SEC-03 (P2, fix now).** `validated_html_archive` omits the USTAR `prefix`, `linkname` and uid/gid checks that its sibling `validated_report_bundle` performs, so a long project path split into `prefix` + `name` can carry `..` past the `./` rooting check. Extract one shared closed-USTAR validator and use it for both bundles; add a fixture with a non-empty `prefix` containing `..` and assert rejection.

**V-SEC-04 (P2, fix now).** The ADR-065 mount matrix test is circular (the fixture and the expectation both come from `Phase::coverage_target_writable()`), and the only literal assertion omits the three export phases while nothing pins the keeper. Add a table-driven test with literal expectations for every phase: keeper not writable, `CoverageRun` and the three `CoverageReport` formats writable, the three `ExportCoverage*` and every non-coverage phase without the mount at all.

**V-SEC-05 (P2, fix now).** `source_stable` is structurally always true (it re-encodes the same immutable bundle and compares it with itself) yet it is published in the mutation tool's schema as `source_unchanged` — "the captured host source was byte-identical before and after the run" — and it is a required clause of a clean result. Decision: **remove the field and its `clean()` clause**; do not ship a schema field that cannot be false. Regenerate the mutation snapshot deliberately, state the before/after SHA-256, and record in `docs/tools.md` and `docs/security-model.md` that host-source immutability is enforced by the read-only `/source` mount plus the applied-mount verification, and evidenced by the gate's host-side canary test — not by a per-response claim. Keep and, if you can strengthen it cheaply, strengthen that runtime canary test.

**V-SEC-06 (P3, fix now).** Gate `with_fault_injection` and `with_clock_source` behind `#[cfg(any(test, feature = "test-hooks"))]` (or add a `scripts/check-architecture.py` rule forbidding those symbols outside test targets) so a future production wiring cannot install a clock and defeat the durable watermark floor.

**V-SEC-07 (P3, fix now).** Couple the mirrored `M2_RECOVERY_HEADROOM_BYTES` to M2's own constant (make M2's `pub(crate)` and assert equality in a `project-adapter` test, or move the constant to domain and have M2 consume it) so a future M2 change cannot silently stop protecting its own commit headroom.

**V-SEC-08 (P3, fix now).** On a step timeout, `scripts/test-m3-runtime.py` must snapshot the owned Docker containers and volumes into the receipt before the kill and again after, so residue is recorded evidence rather than something an operator quietly removes; and give `scripts/test-rust-execution.py` the same per-step bound.

**V-SEC-09 (P3, fix now).** Record the decision that quality Resource reads are deliberately off the worker permit as an explicit amendment inside ADR-060 (it currently says the opposite), and apply the same `ready` bootstrap gate to the quality Resource branch that M1 reads use.
